    Type Alias RequestRegistryTokens

    Gets Paratext Registry access tokens that identify the current user to a service the extension names, using the user's existing Paratext registration. The registration code never leaves Platform.Bible.

    To receive this, an extension lists requestRegistryTokens in its manifest's elevatedPrivileges and lists the services it may request tokens for in paratextRegistryTokenResources:

    {
      "elevatedPrivileges": ["requestRegistryTokens"],
      "paratextRegistryTokenResources": ["https://assistant.example.org"]
    }

    getAccessToken

    • getAccessToken(
          request: RegistryAccessTokenRequest,
      ): Promise<RegistryAccessToken>

      Gets an access token for request.resource. Tokens are cached, so call this before each request to the service instead of storing the token.

      Call this, and the service, from extension-host code. Never return the token from, or store it in, a command, network object, data provider, web view state or web view message: commands are callable by every extension and web views are same-origin, so any other extension could read it there.

      Send the token only to request.resource: whoever receives it can call that service as the user until it expires, so build request URLs from the resource instead of accepting them from callers.

      Rejects with a PlatformError. Its code says why; its message is an English diagnostic for logs, so show users your own localized text based on the code:

      • PERMISSION_DENIED: resource is not in the manifest's paratextRegistryTokenResources, or the Registry accepted the registration but refused to issue the token (HTTP 403), which registering again won't fix
      • INVALID_ARGUMENT: a scope is not allowed, or the Registry rejected the request (for example, the resource is not registered with this Registry)
      • UNAUTHENTICATED: the user has no valid registration, or the Registry did not accept it
      • FAILED_PRECONDITION: the user's Internet & connectivity settings block it: internet access is off, or "Disable access to some Bible translation services" is selected and this computer's location is restricted or could not be determined
      • UNAVAILABLE: there is no internet connection, reading the registration or the Internet & connectivity settings failed or took too long, or the Registry could not be reached or did not return a usable token; retrying later may help

      Other failures, such as a request that times out, reject without a code. Treat them like UNAVAILABLE.

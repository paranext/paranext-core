# Component Choices

Consistent usage of components across the application allows users to easily learn and use the application. They will know how to interact with the controls and what to expect from them.

It is an ongoing effort to review and agree on components and variants for common usage. Internal notes about this can be found [here](https://docs.google.com/document/d/1gKmb2PnCWtRAbVN8ERskRRy-IoTRTsEpC4-kpgEvzxY/edit?tab=t.cmhqjv2sbcd#heading=h.feldja1s1r8b)

## Table and list

For lists and tables, apply the [listbox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/examples/listbox-scrollable/) to make it [accessible](#)

- Code: [listbox-keyboard-navigation.hook.ts](https://github.com/paranext/paranext-core/blob/main/lib/platform-bible-react/src/hooks/listbox-keyboard-navigation.hook.ts)

For tables, use

- [Table](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/shadcn-table--docs)
- Data Table

For lists, use

- [Item](https://ui.shadcn.com/docs/components/item)

Lists may be styled like a single column table **or** as a list of Card-like items.

- See [Result Card](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/basics-resultscard--docs)

List entries and table rows may use context menus and [Ellipsis](https://lucide.dev/icons/ellipsis) button to display more options in context of the item under the cursor.

There is a consistent selection and hover style for all lists, that is

- hover: `tw:bg-muted`
- selected: `tw:bg-muted/50`

There are consistent interaction patterns for lists, see [Interactions/Scripture editor ↔ Lists](https://github.com/paranext/paranext-core/blob/main/lib/platform-bible-react/src/stories/guidelines/application-interactions.mdx#scripture-editor--lists)

## Single and multi select options, Filters

Using the

- [Select](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/shadcn-select--docs) component - for simple selections with little options
- Combobox component - where search, grouping and more details are helpful
  - [Single Select Combobox](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/basics-combobox--docs): use a [Chevron Down](https://lucide.dev/icons/chevron-down) icon on the trigger, close on selection
  - [Multi Select Combobox](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/advanced-multiselectcombobox--docs): use the default [Chevrons Up-Down](https://lucide.dev/icons/chevrons-up-down) icon on the trigger, do not close on selection

Make sure to

- Show the selection with a check mark on the start side, not on the end side like the [default New York style](https://ui.shadcn.com/docs/components/select). This applies to Select, Combobox and other Command lists, and to the checkbox and radio items of dropdown, context and menubar menus
  - In a list where rows can be checked, keep the check's space on every row so all labels line up (for `CommandItem`, pass `data-checked={isSelected}` on every row)
  - In menus whose items have icons, an item keeps its icon and a smaller check sits after it, where the label would otherwise begin
- Provide context by using headings and grouping
- Apply sorting
- Do not break the default component's focus and hover styles, overflow and grow-shrink behavior (if any, improve it)
- Single select and multi select Combobox should behave the same - despite selection mode and different icon

## Zero states

When a list, grid, or panel has nothing to show, say so — do not leave the region blank.

For a plain one-line message, use

- [EmptyState](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/basics-emptystate--docs) - takes a single localized `message` and renders it in a `role="status"` region

For a zero state that needs media, a heading, or a call to action, use

- [Empty](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/shadcn-empty--docs) - the composition `Empty` / `EmptyHeader` / `EmptyMedia` / `EmptyTitle` / `EmptyDescription` / `EmptyContent`

Make sure to

- Say what is empty and what the user can do next, not just "No items"
- Add `role="status"` yourself when using `Empty` for a region whose content just changed, and keep that element mounted across the change so it is announced
- Pass a border width (`tw:border`) when you want `Empty`'s dashed outline - the component sets the dashed style only
- Nest your own heading element inside `EmptyTitle` when the zero state is a region's entire content, since `EmptyTitle` renders a `<div>`

## Wizards

For a task the user completes in a fixed sequence of steps — first-time setup, creating something that needs several decisions, an import with options — use

- [Wizard](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/basics-wizard--docs) - takes the steps (title, content, and whether the user may move on) and provides the step indicator, the [WizardStepper](https://paranext.github.io/paranext-core/platform-bible-react-storybook/?path=/docs/basics-wizardstepper--docs), and Back / Next / Finish (and optional Cancel) buttons

Use a wizard only when the steps depend on each other or must happen in order. When the user can fill things in in any order, use a single form, or Tabs for groups of settings.

Make sure to

- **Keep the wizard's height constant across steps.** Moving to another step must not make the wizard grow or shrink: the Back and Next buttons stay exactly where they were, so the user can click Next repeatedly without chasing the button, and the surrounding layout does not jump. `Wizard` does this for you by sizing itself to its largest step; if you build a stepped flow without it, reserve the height of the largest step yourself
- Keep steps short and roughly balanced in size, since the smaller steps are shown in the space the largest one needs
- Gate Next on the step's own validation (`canAdvance`) instead of showing an error after the click
- Keep each step's content in the step - do not add or remove content outside the wizard when the step changes
